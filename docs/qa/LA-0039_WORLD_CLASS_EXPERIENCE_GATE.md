# LA-0039 World-Class Experience Gate

Status: ACTIVE
Applies to: LA-0039
Decision: PASS / ITERATE / RETURN

## Automatic RETURN conditions

Return before broad polish if any is true:
- the app still looks primarily like stock/default Material 3;
- the Home surface cannot communicate current material + current state + one next action in a glance;
- visual reward exaggerates or fabricates learning progress;
- active-learning result hierarchy is less clear than the current implementation;
- navigation becomes less predictable;
- companion placement competes with content;
- narrow phone / Turkish text breaks the representative flow;
- reduced-motion mode loses semantic meaning;
- a competitor treatment is copied rather than independently implemented;
- production asset cost expands without a proven experience role.

## Required PASS chain

MATERIAL IDENTITY
-> CURRENT LEARNING STATE
-> ONE PRIMARY ACTION
-> ACTIVE LEARNING INPUT
-> TRUTHFUL RESULT
-> SOURCE SUPPORT / UNCERTAINTY
-> EXPLAINABLE NEXT ACTION
-> RETURN CONTINUITY

## 3-second gate

A cold reviewer should identify without explanation:
- this is a learning/study product;
- the current material or first-source action;
- the most important next action.

## 10-second gate

Reviewer can explain:
- what the app helps them do;
- why it is more than a PDF reader/TTS player;
- what they should do next.

## 60-second gate

Prepared-material returning user can reach a meaningful learning action with minimal friction.

No tooltip tour should be required to understand core navigation.

## Payoff gate

After a Recall/Explain-Back result:
- outcome is perceptible immediately;
- source grounding is accessible;
- uncertainty/assistance is not hidden;
- next action is obvious;
- success feedback is satisfying but does not claim unsupported mastery.

## Whole-product coupling gate

Home, Workspace, Listen, Recall/Explain, Progress and navigation must feel like one product system.

A visually excellent isolated screen does not compensate for a fragmented product flow.

## Visual identity gate

At least one representative screenshot should be recognizable as Sesli Öğren without relying on the title text alone.

Recognition must come from:
- composition;
- semantic color roles;
- material/learning hierarchy;
- D/Knot functional integration;
- consistent component language.

Do not rely on ornamental gradients or generic illustrations.

## Asset gate

For each signature asset family record:
- role;
- state;
- source/provenance;
- production method;
- runtime integration;
- accessibility/readability;
- replacement/rollback path.

## Interaction-feel gate

For key transitions:
tap/input -> acknowledgement -> state change -> result -> next action.

Motion:
- must be bounded;
- must not delay learning;
- must preserve meaning under Reduced Motion;
- must never alter evidence/state truth.

## Accessibility / resilience gate

Representative screens:
- no essential color-only distinction;
- touch targets remain comfortable;
- text scales without critical clipping;
- Turkish long strings survive;
- safe areas respected;
- narrow-phone width survives;
- destructive actions retain explicit confirmation;
- focus/semantics remain usable.

## External replacement test

Against strong alternatives such as Speechify, Quizlet, Headway, Brilliant and Gemini Notebook, answer concretely:
Why would a learner open Sesli Öğren for their own material?

PASS answer must be product-specific:
because the same material remains connected across listening, active retrieval/explanation, truthful evidence and an explainable next action.

"Different UI", "AI", "audio", or "looks nice" is not enough.

## Million-Dollar Quality Audit

This is a quality ambition, not a revenue forecast.

PASS requires no obvious structural presentation ceiling in:
- acquisition clarity;
- first-use desirability;
- learning payoff;
- continuation;
- visual recognition;
- long-session usability;
- scalable component/asset system.

## Final disposition

PASS:
representative product experience is strong enough to justify broad remaining V0 polish.

ITERATE:
core direction is sound; one bounded presentation/interaction correction remains.

RETURN:
treatment or coupling is structurally wrong; do not keep polishing the same solution.
