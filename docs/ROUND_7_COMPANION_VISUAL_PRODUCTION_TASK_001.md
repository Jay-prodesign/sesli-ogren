## Governing rule
The approved design plan is authoritative. Production difficulty is not design input. D/Knot and E/Tilt may not be redesigned to suit an image generator, rig tool, or runtime.

## Animation-first F0
F0 is **Canonical Form + Motion Anatomy + Early Runtime Fit**, not a static-art gate. Form and motion are explored together. Each candidate must establish canonical form, silhouette/minimal-size survival, body-integrated attention/expression, restrained idle life, listening/thinking/speaking deformation and early rig/deformation feasibility before F1.

Before six-state multiplication, a candidate that passes source-form jury must also be exercised through the existing CompanionRenderer seam as a bounded runtime smoke test. The smoke test is not a technology lock and does not select a winner. It exists to catch form/readability/integration failures before multiplying assets.

## Asset lifecycle
R7-01 uses one explicit lifecycle:

`locked product/design truth -> asset classification -> canonical master -> isolated reusable source asset -> jury -> runtime integration -> real-context acceptance -> KEEP / bounded refine / REJECT -> only then multiply descendants`

Asset classification for Round 7:
- **AUTHORED / REFERENCE-LOCKED:** Companion canonical master, identity-carrying source assets, state descendants and motion keys.
- **PROCEDURAL / RUNTIME:** focus/attention effects, generic state transitions, layout geometry, non-identity feedback and accessibility-safe presentation behavior.
- **DERIVED:** minimal-size, monochrome, state, motion-key or hero derivatives that retain the canonical master identity.
- **DEFER:** decorative enrichment not required to close R7-01.

Do not use image generation for state or feedback that is better expressed deterministically from runtime truth.

## Canonical master and descendant rule
Each finalist family may have only one current canonical master/reference at a time.

After a master is accepted as the current source reference:
- every identity-critical descendant must derive from that master/reference wherever the production surface supports reference-based generation/editing;
- a derivative may not silently redefine or supersede the master;
- if a derivative drifts, the master wins unless an explicit design decision changes the master;
- rejected outputs are negative evidence only and may not become identity references.

## Isolated source-asset rule
When a reusable production component is required, produce the source asset itself, not only a presentation board.

For composable Companion source assets:
- use clean isolation / transparent alpha when the target production surface supports it and runtime composition requires it;
- keep generous safe margins and avoid baked environment, cast shadow, text, UI, particles or decorative effects unless the asset contract explicitly requires them;
- do not crop production assets from a board;
- compose boards/contact sheets only from source assets that already passed their source jury.

Full-background or intentionally full-frame artwork is exempt from transparency when the composition itself is the asset.

## Mandatory generate -> jury -> repair loop
For each candidate and stage:
1. Lock the canonical target and parity contract.
2. Compile the internal generation prompt from the locked spec.
3. Generate **one candidate only**.
4. Jury the result against the immutable contract.
5. Any hard fail means **REJECT**.
6. Jury outputs failure codes plus concrete visible reasons; it does not invent a replacement design.
7. Compile a corrective prompt from those failure codes and explicitly preserve traits that already pass.
8. Regenerate and re-jury.
9. Repeat until SOURCE VISUAL PASS or change production surface/workflow if the same failure class persists.

A **SOURCE VISUAL PASS is not a PRODUCTION ASSET PASS**.

## Two acceptance levels
### SOURCE VISUAL PASS
Means the isolated generated/authored source satisfies the locked visual contract, lineage and hard-fail rules.

### PRODUCTION ASSET PASS
Requires SOURCE VISUAL PASS plus actual bounded application integration.

For Companion F0/F1 this includes, as applicable:
- render through the real CompanionRenderer seam rather than a board-only mock;
- preserve semantic state ownership in CompanionView / canonical learning state;
- minimal-size readability;
- dense-learning-screen readability;
- teen/adult/professional context credibility;
- silhouette/monochrome survival;
- Reduced Motion / minimal fallback compatibility;
- no layout/accessibility regression attributable to the asset;
- no identity drift after integration.

Only PRODUCTION ASSET PASS may replace a proven runtime placeholder or become the basis for broad descendant multiplication.

## Placeholder atomic-replacement rule
Existing proven fallback/provisional renderers remain available until the candidate is integrated and passes production-context acceptance.

Do not remove a working placeholder first and then hope the new asset works.

A replacement is accepted only when:
- the new candidate is integrated;
- semantic behavior remains correct;
- the target context remains readable;
- rollback to the prior renderer remains straightforward during the bounded proof.

## Semantic authority firewall
Visuals may **read and express** learning/product truth; they may not create or mutate it.

Companion rendering must not independently decide:
- LearnerEvidence;
- LearnerState;
- mastery/readiness;
- success/correction truth;
- next-best learning action;
- pedagogical progression.

The renderer receives canonical state and expresses it. Visual code/art may never manufacture a stronger learning claim than the underlying evidence supports.

## D/Knot
Living, calm, intelligent interlaced character. Two broad continuous ribbons, deliberate over-under logic, negative space, asymmetry and structural tension carry identity. Attention uses body-integrated apertures/tension points, never conventional eyes. It must not become a decorative knot/logo.

## E/Tilt
Upright directional living character. Whole-body tilt plus integrated facet/notch carries orientation. No floating marker, robot/device, humanoid teacher or generic upright blob.
