# LA-0026 — Active Explain-Back

- **Status:** ADMITTED / READY
- **Handoff:** Post-LA-0025 commercial learning-value tranche
- **Executor:** ChatGPT (bounded reversible engineering)
- **Owner / verifier:** Brain
- **Authority:** D-054, D-073, D-074, D-076 and the post-M5 premise audit

## Need
LA-0025 adds truthful source-grounded teaching, but explanation consumption is deliberately passive and creates no learner evidence. Canonical V0 requires EXPLAIN to include a bounded learner explain-back interaction, gap-aware feedback, one targeted follow-up, and durable evidence. Without that active half, Explain is useful but not yet a complete learning mode.

## Decision
Extend the existing Material/Recall learning truth rather than creating a separate quiz/tutor system. Add one bounded text-first explain-back path tied to the exact current source. The learner explains the idea in their own words; server-authoritative evaluation records what was actually observed, returns uncertainty-aware feedback, and recommends one targeted repair/re-attempt. Generated teaching remains distinct from learner evidence.

Voice response is not required in this tranche. Do not activate a paid/live provider. Where semantic evaluation requires an unavailable provider, fail closed rather than infer mastery from deterministic or client-side heuristics.

## First production slice
1. From grounded Explain, offer **Kendi cümlelerinle anlat** as the active evidence-producing continuation alongside Recall.
2. Capture a bounded learner text explanation against the current material/source version.
3. Persist an explain-back attempt/evidence record with assistance/provenance and source binding.
4. Return truthful feedback states: sufficient evidence, partial/gap detected, or not evaluable.
5. For partial/gap, show one source-grounded targeted repair and one re-attempt path.
6. Reopen preserves the explain-back evidence/continuation.
7. Home/Material progress may reflect explain-back evidence only through the canonical learner-state derivation; passive Explain remains evidence-neutral.

## Out of scope
Continuous tutor chat, full-duplex voice, generic quiz/flashcard UI, broad challenge taxonomy, calibrated mastery/readiness probability, client-side semantic scoring, new AI provider/vendor selection, paid API activation, generic AI framework extraction, gamification/economy.

## Acceptance
- Attempt is bound to the learner-owned current material/source and stale/wrong source fails closed.
- Passive explanation alone creates no evidence.
- Explain-back evidence is durable and idempotent.
- Assistance/repair history prevents assisted success from becoming independent mastery.
- Feedback is uncertainty-aware and does not overclaim.
- One targeted repair/re-attempt loop works and survives reopen.
- Cross-account access is rejected server-side.
- UI clearly distinguishes source, generated teaching, learner response and evaluated evidence.
- One bounded tranche checkpoint passes before DONE.

## Reuse / provenance
Reuse the accepted server-authoritative Recall assistance/evidence patterns and LA-0025 grounded generation boundary where they fit. Do not create a parallel evidence store or a second generation stack.

## Escalation
Escalate before selecting/activating a paid provider, changing canonical mastery semantics, adding voice capture permissions, or widening into continuous tutoring.
