# LA-0020 — Active learning action → LearnerEvidence → LearnerState → next action

- **Status:** IN_PROGRESS
- **Handoff:** CLAUDE_HANDOFF_002
- **Executor:** ChatGPT (temporary reversible engineering authority)

## Objective
Implement the smallest truthful learning-intelligence loop: one meaningful active action produces durable evidence, bounded deterministic state and an explainable next action.

## Authoritative source references
- D-071 — M5 Golden Learning Slice explicit admission
- D-037 learner evidence/state direction
- D-053 / D-054 context-adaptive V0 authority
- M5_GOLDEN_LEARNING_SLICE_ACCEPTANCE_CONTRACT_v0.1
- QA_RELEASE_GATES — Learning App

## In scope
- One meaningful Recall/Explain/Focus learning action grounded in the admitted source.
- Canonical LearnerEvidence event/schema.
- Minimal deterministic LearnerState derivation.
- Explainable next-action rule and reason.
- Distinct strong/partial/misconception/unknown or equivalent bounded outcomes where supported.
- Reuse: current Round 7 evidence-branch semantics where they match M5 truth; NO_APPROVED_CANDIDATE for any new generic learner-model framework.

## Out of scope
- Full mastery model, spaced-repetition engine, recommender platform, adaptive ML, opaque model-authored mastery.
- Engagement events as learner truth.
- Passive listening/time/taps creating readiness/mastery.

## Dependencies
- LA-0019

## Steps
1. Define versioned evidence and minimal state contracts.
2. Implement one source-grounded active action and deterministic evaluation path.
3. Persist evidence before deriving state.
4. Derive next action with a human-readable rationale/reason code.
5. Add anti-farming, helped/unknown and stale-source tests.

## Acceptance criteria
- Same evidence + rule version yields the same bounded state and next action.
- Passive behavior cannot improve real learner state.
- Wrong/partial/helped/unknown outcomes do not collapse into one result.
- Next action is inspectable/explainable and references valid source/evidence context.

## Required tests / evidence
- Determinism tests.
- Evidence-before-state persistence tests.
- Anti-farming/replay tests.
- Stale source/version invalidation tests.
- Negative tests for fabricated mastery/readiness.

## Rollback / migration notes
Keep rule versions explicit. Any state-schema migration must preserve/recompute truth from canonical evidence rather than mutate evidence history.

## Escalation conditions
A requirement for probabilistic/opaque learner-state inference, high-risk schema reinterpretation, or production model/provider credentials.

## Expected return
Return the exact evidence schema, rule version, state semantics, next-action examples and test evidence before LA-0021.
