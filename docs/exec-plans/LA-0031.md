# LA-0031 — Material deletion + safe continuity

## Status
IN_PROGRESS

## Objective
Close the V0 Library deletion gap without inventing a second data model or a generic privacy framework.

## User-visible contract
- A learner can delete a material from Library after explicit confirmation.
- The deleted material disappears from active Library/Home selection.
- If the deleted material was the most recent continuation target, Home falls back to the next most recently active material.
- Existing source-store deletion semantics remain authoritative: source content is revoked/redacted and dependent learning truth is removed through the existing relational cascade.
- The UI must not claim account-wide deletion or remote deletion that the current local runtime does not perform.

## Implementation boundary
- Reuse SourceStore.deleteMaterial; do not create a new deletion service.
- No undo/trash system in V0.
- No account deletion in this task.
- No server/admin/billing work.
- No new generic privacy abstraction.

## Acceptance
1. Library exposes a clear delete control.
2. Confirmation is required.
3. Deletion refreshes Library and Home safely.
4. Store-level deletion remains learner-scoped and fail-closed.
5. Widget regression covers deleting the newest of multiple materials and fallback to the remaining material.
6. Strict format, analyze and bounded Flutter test pass.

## Validation note
The product validation workflow uses an explicit bounded test timeout and expanded reporter so a stuck Flutter test fails diagnostically instead of consuming the full job timeout.
