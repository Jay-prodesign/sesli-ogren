# LA-0034 — Secure account + data deletion

- **Status:** IN_PROGRESS
- **Handoff:** Post-LA-0033 first-commercial-V0 completeness
- **Executor:** ChatGPT (bounded reversible engineering)
- **Owner / verifier:** Brain

## Objective
Ship a real authenticated account/data deletion path without exposing privileged credentials to Flutter or pretending local-only deletion is account deletion.

## In scope
- Authenticated, idempotent server deletion intent that marks the account `deletion_requested`.
- Immediately block normal user RPC work through the existing `la_require_user()` active-account guard.
- Cancel queued/in-flight retryable generation jobs for the deleting account.
- Server-only Supabase Edge Function that validates the caller JWT, inventories and removes owned source Storage objects, revokes sessions, then deletes the Auth user.
- Flutter deletion gateway + explicit destructive confirmation.
- Learner-scoped local SQLite purge after remote deletion succeeds.
- Post-delete app state that does not silently reopen the deleted learner.
- Disposable PostgreSQL regression + Edge Function type-check + Flutter regression.

## Out of scope
- Hosted production migration/deployment before the canonical server substrate is actually applied to the connected Supabase project.
- Grace-period/undo deletion.
- Legal retention export workflows.
- Billing cancellation/refund logic.
- Admin dashboard.

## Security invariants
1. No service-role/secret key enters Flutter/client code.
2. User id comes only from validated Auth JWT, never request body.
3. Storage objects are removed before Auth user deletion because Supabase blocks deletion of users who still own Storage objects.
4. Session refresh tokens are revoked before Auth user deletion; access JWT expiry remains a platform property.
5. Failed remote deletion must not be represented to the user as complete.
6. Local learner data is purged only after remote hard-delete returns success.
7. Other learners on the same device/database remain untouched.

## Dependencies
- LA-0033

## Acceptance
- Server SQL + Edge Function gate passes.
- Flutter format/analyze/tests pass.
- Successful UI flow invokes the authenticated deletion boundary once, purges only the current learner locally and transitions to explicit deleted state.
- Failure path preserves local data and does not claim deletion success.
