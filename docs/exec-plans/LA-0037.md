# LA-0037 — Safe local sign-out + account switching boundary

- **Status:** IN_PROGRESS
- **Handoff:** Post-LA-0036 first-commercial-V0 account/settings continuity
- **Executor:** ChatGPT (bounded reversible engineering)
- **Owner / verifier:** Brain

## Objective
Complete the basic account-session lifecycle by letting an authenticated learner intentionally sign out on the current device without deleting their account or learner data.

## Authoritative source references
- D-054 / V0_PRODUCT_SCOPE_v2.0 — Profile / Settings includes account controls.
- LA-0036 — passwordless account entry + existing-session restore.
- Existing learner-id-scoped SQLite contracts — local data remains isolated by authenticated learner identity.

## In scope
- Explicit Profile action: “Bu cihazda çıkış yap”.
- Confirmation that sign-out is not account/data deletion.
- Supabase Auth local-scope sign-out.
- Root runtime closes only after sign-out succeeds.
- Successful sign-out returns to AccountEntryScreen.
- Learner-scoped local SQLite data is preserved for later same-account resume.
- Failure keeps the current authenticated runtime open and shows a retryable error.
- Widget regression for confirmation, callback and local-data preservation.

## Out of scope
- Global/all-device sign-out.
- Account deletion (LA-0034 owns that behavior).
- Local cache purge on ordinary sign-out.
- Account merge or anonymous identity migration.
- Hosted Supabase configuration or secrets.

## Security / continuity invariants
1. Sign-out and account deletion remain visibly different actions.
2. No local learner data is deleted by ordinary sign-out.
3. Runtime is not closed/routed to account entry until Supabase sign-out succeeds.
4. Another signed-in learner cannot read prior learner data because all local access remains learner-id scoped.
5. No service-role or privileged credential is involved.

## Dependencies
- LA-0036 DONE.

## Acceptance criteria
1. Profile exposes local-device sign-out.
2. Confirmation copy states that account/data are not deleted.
3. Successful callback occurs once and local learner data remains.
4. Failed sign-out does not route away from authenticated runtime.
5. Canonical format, Flutter analyze and bounded expanded tests pass.

## Required tests / evidence
- Widget test proves confirmation is required before sign-out callback.
- Widget test proves successful sign-out callback runs exactly once.
- Existing learner material remains present after ordinary sign-out callback.
- Bootstrap validation passes.
- Product bounded validation passes canonical format, Flutter analyze and expanded Flutter tests.

## Rollback / migration notes
Client-only account-session flow change. No database migration and no hosted Supabase mutation. Reverting the Profile/root/auth changes restores the prior no-sign-out state without changing stored learner data.

## Escalation conditions
- Stop before adding all-device/global sign-out semantics.
- Stop before purging local learner data during ordinary sign-out.
- Stop before changing hosted Supabase Auth settings, credentials or provider configuration.

## Expected return
A learner can intentionally exit the current device session, return to account entry, and later sign back into the same account without losing learner-scoped local continuity.
