# LA-0038 — Truthful support contact surface

- **Status:** IN_PROGRESS
- **Handoff:** Post-LA-0037 first-commercial-V0 Profile / Settings completeness
- **Executor:** ChatGPT (bounded reversible engineering)
- **Owner / verifier:** Brain

## Objective
Close the canonical V0 Profile / Settings support gap without inventing a support identity or coupling the app to a provider that has not been selected.

## Authoritative source references
- D-054 / V0_PRODUCT_SCOPE_v2.0 — Profile / Settings requires support.
- Current Learning App canonical records — no production support email is defined yet.
- App-first / fail-closed rules — do not present unverified contact details as product truth.

## In scope
- Client-safe compile-time `SUPPORT_EMAIL` configuration.
- Validate the configured value before showing it.
- Profile support card shows the real configured email when valid.
- One-tap copy action using Flutter platform clipboard.
- Missing/invalid configuration shows an explicit unavailable state and no fake email/button.
- Widget regression for configured and unconfigured states.

## Out of scope
- Selecting or purchasing a support/helpdesk vendor.
- Sending email directly from the app.
- Ticket backend, CRM, chat or WhatsApp integration.
- Legal/privacy policy URLs.
- Hosted Supabase or production service mutation.

## Security / truth invariants
1. Support contact is client-safe public configuration only.
2. No secret, token or credential is used.
3. Empty/invalid support configuration cannot render a fake contact.
4. Support failure does not block learning flows.
5. Runtime support copy must reflect only the configured address.

## Dependencies
- LA-0037 DONE.

## Acceptance criteria
1. Valid configured support email is visible in Profile.
2. User can copy the address.
3. Missing/invalid configuration produces a truthful unavailable state.
4. No invented fallback address exists in source.
5. Canonical format, Flutter analyze and bounded expanded tests pass.

## Required tests / evidence
- Widget regression with a configured support email.
- Widget regression with empty support configuration.
- Bootstrap validation.
- Product bounded validation: canonical format, Flutter analyze and expanded tests.

## Rollback / migration notes
Client-only Profile surface change. No database migration and no hosted service mutation. Reverting removes the support card without affecting user data.

## Escalation conditions
- Stop before choosing a public production email/domain on behalf of the Founder.
- Stop before adding a paid support provider or sending capability.
- Stop before adding legal/privacy policy URLs that have not been canonically approved.

## Expected return
The app has a real support-contact surface ready for release configuration, while remaining honest and usable before the public address is selected.
