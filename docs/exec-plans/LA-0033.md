## Objective
Add the missing Profile/Settings surface using existing authenticated account, entitlement and quota truth. Never fabricate plan, quota or usage when server truth is unavailable.

## Authoritative source references
- D-054 / V0_PRODUCT_SCOPE_v2.0 — Profile/Settings requires account, language, voice, accessibility, privacy and plan/usage.
- M4 canonical core — accounts, entitlements and quota_ledger are server-authoritative, authenticated-owner-readable RLS surfaces.
- D-074 — concrete-first; do not create a generic billing/settings framework.

## In scope
- Add Profile as a fourth product-shell destination.
- Read authenticated learner account locale/status, entitlement plan/status and recent quota ledger rows.
- Fail closed with retry when account/usage truth is unavailable.
- Show truthful current language, product-local device TTS, system motion preference and existing material deletion privacy path.
- Widget regression with injected deterministic account overview.

## Out of scope
- Account deletion RPC (next destructive/security tranche).
- Purchase/subscription checkout.
- Changing plan or quota.
- Voice picker.
- New analytics/billing framework.
- Fabricated usage percentages or remaining quota where no matching authoritative limit exists.

## Dependencies

## Acceptance criteria
1. Profile is reachable from the main navigation.
2. Plan and usage come only from RLS-protected server account/entitlement/quota truth.
3. Missing server truth produces an explicit unavailable state, not guessed values.
4. Profile reflects Turkish locale/device TTS/system motion behavior truthfully.
5. Privacy copy points only to implemented material deletion and clearly separates pending account deletion.
6. Existing learning flow remains unchanged.
7. Bootstrap, canonical format, Flutter analyze and bounded tests pass.

## Required tests / evidence
- Widget regression shows injected verified free-plan/usage data and no invented values.
- Existing auth fail-closed tests remain green.
- One bounded product-bounded-validation pass plus bootstrap validation before DONE.

## Rollback / migration notes
Client/UI only; no schema migration. Remove Profile destination and account gateway if rollback is required. Existing M4 account/entitlement/quota schema remains unchanged.

## Escalation conditions
Escalate before introducing checkout, mutating entitlements/quotas, exposing provider identifiers, or implementing destructive account deletion.

## Expected return
A truthful Profile surface that makes account plan/usage and current settings visible without inventing commercial state.
