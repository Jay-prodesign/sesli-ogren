# LA-0032 — Durable Listen resume continuity

- **Status:** IN_PROGRESS
- **Handoff:** Post-LA-0031 commercial-product continuity
- **Executor:** ChatGPT (bounded reversible engineering)
- **Owner / verifier:** Brain

## Objective
Make product-local Listen resume the learner at a durable, source-version-bound checkpoint after leaving or reopening the app, without treating listening as mastery and without building a generic audio platform.

## Authoritative source references
- D-054 / V0_PRODUCT_SCOPE_v2.0 — Listen requires durable playback and resume while passive listening remains evidence-neutral.
- D-068 — physical-device audio validation remains a later release gate.
- D-074 — use the smallest concrete implementation and QA needed for the current product behavior.

## In scope
- Deterministic bounded text chunking for device TTS.
- Learner/material/current-source-version-bound persisted Listen chunk position.
- Resume and restart controls in the existing Listen surface.
- Automatic progression across chunks and reset to the beginning after complete playback.
- Schema migration from database v6 to v7.
- Widget and migration regressions.

## Out of scope
- Background playback / lock-screen media controls.
- Cross-device audio sync.
- Generated audio caching or cloud TTS.
- Voice catalog/settings.
- Learning evidence, mastery or progress changes from listening.
- Shared Speech Service extraction.

## Dependencies
- LA-0031

## Acceptance criteria
1. Listen resumes from the persisted chunk for the exact current source version.
2. A changed/superseded source cannot inherit an old source checkpoint.
3. Stopping preserves the current chunk; completing the final chunk resets resume to the beginning.
4. Resume state survives SQLite close/reopen.
5. Material deletion removes Listen resume state.
6. Passive listening remains evidence-neutral.
7. Strict format, Flutter analyze and bounded tests pass.

## Required tests / evidence
- v6→v7 migration preserves unrelated data and creates listen_progress.
- Widget test exercises resume from a persisted checkpoint and completion reset.
- Existing deletion/source-authority regressions remain green.
- One bounded product-bounded-validation run must pass before DONE.

## Rollback / migration notes
Rollback is code-level: remove v7 table usage and UI behavior. The additive listen_progress table contains only resumable playback position and may safely remain unused if rollback occurs. No destructive migration is required.

## Escalation conditions
Escalate only if platform TTS cannot reliably complete bounded utterances, if source-version identity cannot safely scope resume state, or if background playback becomes necessary to satisfy the accepted V0 release contract.

## Expected return
A passing branch where Listen visibly resumes from a durable source-bound checkpoint, with no new mastery semantics or shared speech infrastructure.
