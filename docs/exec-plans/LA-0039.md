## Intent

Turn the existing production-shaped Learning App runtime into one coherent, premium, recognizable product experience without weakening learning truth or expanding unrelated feature scope.

This is not a cosmetic recolor task.

## Product problem

Current UI works but still reads as a prototype because:
- generic Material defaults dominate;
- surfaces are visually interchangeable;
- material identity is weak;
- state/next-action hierarchy is weak;
- active-learning payoff is under-expressed;
- Listen, Recall, Explain, Progress and Home do not yet feel like one product;
- companion and motion do not yet create enough functional continuity.

## Golden Product Slice

Primary returning-user path:
1. Home shows active material, truthful current state and one primary next action.
2. User enters Material Workspace.
3. User starts one active Recall or Explain-Back action.
4. Input gets immediate acknowledgement.
5. Result clearly distinguishes:
   - what the learner did;
   - what evidence means;
   - source support;
   - what remains uncertain;
   - exact next action.
6. User returns to Home and sees continuity reflected.
7. If Listen is active/available, playback continuity is obvious and non-competing with the active-learning CTA.

Secondary activation path:
- no-material Home makes adding the first source obvious;
- source ingest remains the shortest credible path into learning.

## Adapted product-quality systems

### Whole-product coupling
Every representative surface must reinforce:
material -> action -> evidence -> next action -> return.

### Payoff ladder
- NOW: clear next tap.
- SESSION: truthful, satisfying result.
- NEXT SESSION: visible unfinished next action.
- MULTI-SESSION: material-level evidence continuity without fake mastery percentages.

### Cold/fresh-player stress
Static/red-team first; human sample later when representative runtime is ready.

Required questions:
- what is this app for in 3 seconds?
- what should I tap in 10 seconds?
- can I reach meaningful learning within 60 seconds from a prepared material?
- can I explain what changed after one active-learning result?
- do I know why I should come back?

### Visual-treatment discipline
T2 selected; T1 remains control; T3 contributes interaction principles only.

### Asset manifest
No signature asset enters runtime without role/state/format/accessibility/reuse/QA fields.

### Interaction/game-feel adaptation
Motion/haptic/emphasis may amplify:
input acknowledgement;
state transition;
learning result;
next-action emphasis.
They may never manufacture learning evidence.

### Million-dollar quality audit
Before tranche exit, compare the representative slice against current world-class product quality, not only against the previous app build.
