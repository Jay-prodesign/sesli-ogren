# LA-0040 Concept Truth Audit — Generated Visual vs Current Product

Status: COMPLETE
Purpose: prevent a direction mockup from silently becoming product/scope authority.

## Artifact under review
The four-screen generated concept showing:
1. Home
2. Biology Workspace
3. Recall question
4. Recall result

This artifact is **DESIGN-DIRECTION REFERENCE ONLY**. It is not implementation truth, roadmap authority, or approved feature scope.

## Correct / grounded elements
These are aligned with current implemented or already-authorized Sesli Öğren capabilities:
- own material / Biology notes as the central object;
- PDF or text source identity;
- Home / Library / Progress / Profile shell concept;
- Recall as an active learning action;
- Listen as a passive/supportive mode;
- Explain and Focus as supported learning modes;
- source-grounded result presentation;
- “İpucusuz hatırladın” style evidence-aware copy;
- showing the learner's answer separately from source support;
- next-action continuation;
- material-first visual hierarchy;
- one dominant primary action;
- source-linked study flow rather than generic chat.

## Partially grounded / presentation-only
These may be acceptable as visual forms only if mapped to real data:
- material cover/card visual;
- progress-like bars only if they represent a real, named state (not fake mastery/completion);
- recent-material row only if backed by actual material recency data;
- compact subject/topic chips only if extracted/stored by a real current capability;
- source-page thumbnail only if generated from real PDF/source bytes with valid provenance and runtime support;
- source-derived diagrams only if they come from real source media or an explicitly admitted generated-learning artifact, never as decorative invented truth.

## Not currently justified / must not be treated as real
The generated image includes several concepts that exceed or distort current product truth:

### “12 / 28 konu”
Not current authoritative learner progress.
It visually implies a structured curriculum/topic completion model that the current product does not own.

### “3 / 5” recall sequence
Not current canonical product behavior.
It implies a fixed multi-question session/quiz progression that is not the current Recall contract.

### “Konu listesi” / structured chapters
Not guaranteed by current ingest/data model.
A PDF/text source does not automatically become a validated 28-topic syllabus.

### “Konu görseli” generated photosynthesis diagram
Not current production capability.
A generated diagram must not be shown as though it came from the source unless provenance explicitly says so.

### “Ana kavramlar” chips
Potential future/authorized artifact concept, but not automatically current runtime truth unless the relevant extraction/generation capability is present and grounded.

### PDF page count / page-specific result linking
Page-level references are only valid if actual PDF parsing/runtime contracts expose and preserve that exact page provenance. Do not infer from a design sketch.

### “Son eklenenler” Home composition
The store can support multiple materials/recency, but this exact Home module is a design proposal, not current approved IA.

## Companion truth
The concept omitted canonical D/Knot. That omission is **not** a new product decision.
Prior Learning App work already selected and integrated D/Knot. New visual work should test how canonical D/Knot participates in the stronger system, not silently remove it.

## Roadmap/research reconciliation
Earlier Learning App work had already established that:
- M5 utility/card UI was intentionally not final V0 experience;
- V0 experience should become more living/gameful/premium without corrupting learning truth;
- D/Knot functional presence, current quest/home, learning path/world, challenge framing and richer feedback/motion were recognized experience debt/opportunity;
- benchmark/design process included experience principles, multiple art/experience directions, Founder selection, design system, Owner Preview and then implementation.

Therefore LA-0040 is a **refinement/reconciliation task**, not zero-based discovery.

## Correct next design rule
Every next prototype must label each visible UI element as one of:
1. CURRENT IMPLEMENTED TRUTH
2. CURRENT AUTHORIZED PRESENTATION OF REAL DATA
3. PROPOSED PRESENTATION — NO NEW CAPABILITY
4. FUTURE / NOT ADMITTED

Only categories 1–3 may appear in the implementation-truth Golden Slice.

## Verdict
The generated concept is:
- **GOOD as visual-direction inspiration**
- **NOT SAFE as implementation specification**
- **NOT evidence to remove/redesign D/Knot**
- **NOT evidence to add topic counts, fixed quiz/session counts, generated diagrams or curriculum structures**

The next Golden Slice must keep the stronger visual composition while removing unsupported product claims.
